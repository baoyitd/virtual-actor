v0.4.0 Dossier 终审汇报

角色资产化与使用入口 | 基线 v0.3.0-commercial-trial Accepted | 2026-05-25 | Formal Status: Draft

核心结论

经过研究分析、竞品深度对比、集团企业场景建模和两轮 AI 规划复审，dossier 得出以下结论：

1. virtual-actor 在版本治理、知识追溯和质量门禁上相比所分析竞品具有结构性相对优势，但在资产治理属性、正式使用入口和被系统调用三个维度存在缺口。
2. v0.4 应优先补这三个缺口，主线定位为"角色资产化与使用入口"。
3. 模板库（DD-06）未被真实用户场景推导，已移出本轮 Scope In。
4. A3 执行动作涉及跨系统读写，v0.4 不实现，只定义模型。
5. 消费侧 API 只产出设计说明文档，不改变已有接口。

所有优势判断均基于"当前抽样竞品和已核对证据范围内的相对优势"口径，不使用绝对表述。

Scope Out（9 项）

  • 跨项目读写边界变更 — 不改变知识平台当前依赖边界
  • AI 辅助填充角色配置 — 当前不纳入
  • 角色模板库（DD-06） — 未被真实用户场景推导，移出本轮承诺
  • 多角色协作编排 — 只定义概念，不实现委派机制
  • RBAC / 多租户 / SaaS — v0.3 Scope Out 继续生效
  • 不得把 mock/stub/fixture 描述为真实集成证据

usage_records 数据模型

字段类型说明

9. 风险边界与停止条件

风险边界（5 项）

  • 使用台新增 API 路径 — 如果 /role-assets/{id}/usage 需要新增读写接口，必须先回写 dossier 再实现
  • 资产治理属性 — 如果上位治理要求纳入公共对象，必须先上提裁决
  • 消费侧设计 — 调用拓扑只提建议，不裁决
  • A3 执行 — 如果涉及工具权限或跨系统调用，必须先上提裁决
  • 不得把 mock/stub/fixture 描述为真实集成证据

停止条件（5 项）

  • 1. 实现偏离 design-delta，必须先回写 dossier
  • 2. 使用台需要新增读写接口或改变已有 API 路径，必须先回写 dossier
  • 3. 消费侧设计触发公共契约裁决要求，必须停止相关实现并上提
  • 4. 执行能力定义涉及工具权限或跨系统调用设计，必须先上提裁决
  • 5. 不得把 v0.4 任何 mock/stub/fixture 描述为真实集成证据
