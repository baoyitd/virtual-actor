# v0.5.0 测试计划

版本：v0.5.0 | 日期：2026-06-11 | 状态：Self-Tested | 验收对象：角色定义层重构与外部复用准备设计包

> 本文档用于支撑 `v0.5` 实现验收、测试方独立复核与最终用户测试，不构成 `Accepted` 声明。

## 1. 交付范围

`v0.5` 在 `v0.4` 基线上新增或重构：

1. `DD-17` 角色定义层重构：
   - 新 `L1` 身份与判断
   - `L2` 知识依据双路径
   - `L3` 数据能力（可选）
   - `L4` 输出方式 + 运行配置
2. `DD-18` 角色资产最小说明能力独立为消费契约层
3. `DD-19` AI 协作创建升级，继续保持“自然语言 -> 结构化草案 -> 人确认后保存”
4. `DD-20` 角色创建 / 编辑交互重设计
5. `DD-21` 现有发布门禁补充
6. `DD-22` 对外供给稳定载体
7. `DD-23` 外部复用代表验证与回写闭环
8. `DD-24` legacy 角色兼容与补齐
9. 管理员数据资产管理页

## 2. 不交付范围

1. 独立定义包对象、定义包中心或翻译工作台
2. 完整外部分发中心与通道发布系统
3. 完整动作执行平面、审批链和动作审计系统
4. 六类资产独立对象中心
5. 企业级 RBAC、多租户或完整组织权限体系
6. “负责什么 / 不负责什么”独立字段组
7. 系统能力 / 通用能力 / 执行策略的一体化运行时闭环

## 3. 测试类型与覆盖策略

| 测试类型 | 覆盖范围 | 说明 |
| --- | --- | --- |
| 需求 / 设计评审 | 全范围 | 核对 requirements / scope / design / traceability / UI / tests 一致性 |
| 自动化 API 测试 | `US-22 ~ US-30` | 后续实现阶段覆盖新增字段、门禁、外供生成、回写与兼容，并验证知识绑定、数据能力、输出契约在 `test / consume` 运行时真实生效 |
| 程序化 UI 测试 | `US-22 ~ US-30` | 覆盖工作区、消费契约、治理与发布、数据资产管理、外供、legacy |
| 运行效果型测试 | `US-23` `US-28` | 专门验证配置不是“只显示在页面上”，而是会真实影响平台内测试 / 消费结果与外部复用结果 |
| 外部环境验证 | `US-27 ~ US-28` | 至少两类代表环境：一个 Tool 形态、一个 Skill 形态 |
| 人工手动冒烟 | 高风险路径 | 创建 / 编辑 / 消费前判断 / 发布 / 数据资产管理 / 外供 / legacy |
| 文档验收 | 全范围 | 核对真源一致性，不出现旧 `capability_*` 回流或范围漂移 |

## 5. 核心用户路径

1. 用户通过 AI 或手工方式进入统一工作区并创建角色规格草案
2. owner 在工作区里补齐 `L1-L4`，其中：
   - `L2` 可绑定或不绑定真实知识
   - `L3` 可绑定或不绑定数据资产
   - `L4` 先选 `output_mode`
3. owner 在使用前说明页补齐适用场景、使用说明和可信依据，并在保存当前说明卡后把当前可编辑版本推进到 `test`
4. 平台管理员维护可供角色绑定的数据资产项
5. 用户在调用前通过说明卡判断是否适合使用该角色
6. owner 在 `03` 对 `test` 角色执行内部测试；测试页不再承接 `draft -> test`
7. owner 在 `04` 看到新增硬门禁、软提示和结构化路径条件门禁，并在这里承接 `publish / archive`
8. 说明卡来源变化后，用户能看到`待确认更新`并重新生成或重新确认后再发布 / 外供
9. owner 为已发布角色版本生成 `Tool / Skill` 供给物，且最小文件契约完整
10. 代表性外部环境接入供给物并触发平台侧回写
11. 平台内 `test / consume` 与外部复用结果会真实受到知识绑定、数据能力和输出契约配置影响，而不只是页面展示状态变化
12. `archived` 角色退出活跃市场、正式消费和新外供，但历史追溯仍可查询
13. legacy 角色可继续打开、补齐和受限外供

## 6. 代表性外部环境建议

当前推荐：

1. Tool 形态：`Dify`
2. Skill 形态：`Codex`

若后续在实现计划中需要更换环境，必须先回写 dossier 再继续。

## 7. 停止条件

1. 若设计重新走向独立定义包对象或工作台，必须停止。
2. 若创建 / 编辑页又退回长瀑布表单，必须停止。
3. 若 `L3` 再次退回自由文本能力说明，必须停止。
4. 若 `L4` 把 `freeform` 重新视为未完成状态，必须停止。
5. 若数据资产管理页显著走向重数据治理平台，必须停止。
6. 若外供设计退化为“静态文档”或“裸接口地址”，必须停止。
7. 若外部回写闭环未被纳入设计或测试，也必须停止。
8. 若治理主路径再次退化成纯展示字段，必须停止。
9. 若说明卡来源变化后仍可静默带着旧文本发布 / 外供，必须停止。
10. 若测试仍只校验页面逻辑、字段保存或门禁提示，而未覆盖知识 / 数据 / 输出契约的运行效果，必须停止。
