## 2. 先复现工作方基线

### 2.1 启动稳定 smoke runtime

在一个终端执行：

```bash
npm run smoke:v05:runtime
```

访问入口：

```text
http://127.0.0.1:18080
```

### 2.2 复跑程序化浏览器烟测

在另一个终端执行：

```bash
npm run smoke:v05:browser
```

通过标准：

1. 命令返回 `PASS`
2. 生成 `tmp/v05-browser-smoke/summary.json`
3. 生成 `01 ~ 11` 全套截图

若此步不通过，先阻断，不进入后续人工测试。

## 3. 测试方必须补做的独立测试

### 3.1 真实浏览器 / Human UI 冒烟

建议至少覆盖以下页面和主链路：

1. 角色定义工作台：确认 `L1-L4` 页面组织、placeholder、数据资产绑定、AI 草案填充体验。
2. 使用前说明与调用预览：确认说明卡是主结构，`待确认更新 -> fresh` 路径清晰。
3. 治理与发布：确认 `owner / business_domain / category` 的阶段性硬门禁。
4. 外供与追溯：确认 `Tool / Skill` 包结构预览、旧包提示、模拟外部调用结果展示。
5. 正式消费：确认前置说明卡、结果展示、`freeform / structured` 表达。
6. 资产市场：确认列表发现、AI 推荐、无匹配 / out_of_scope 表达。

重点人工用例请对照：

1. `delivery/test-cases-v0.5.md` 中 `H201 ~ H221`
2. 尤其是 `H203-H220`、`H209-H221`

### 3.2 代表环境真实调用

这是本轮最关键的代表环境验证项，已完成闭合。

必须至少完成：

1. `Dify` 导入 `Tool package`，完成一次真实调用
2. 平台侧验证 `usage_record`、`role_id`、`role_version_id`、`status`、`boundary_status`、输出契约回写完整

本轮已在本地真实 `Dify` 环境完成闭合，不再是阻塞项。

### 3.3 运行效果复核

除页面路径外，测试方应再独立确认以下运行效果，不接受“页面显示正常”替代：

1. 知识绑定与未绑定，对同类问题的结果确实不同
2. 数据资产绑定与停用，对结果有真实影响
3. `freeform / structured` 切换后，运行结果形态符合契约
4. 外部复用后的结果，不绕开知识 / 数据限制

## 4. 测试方输出要求

测试方完成后，至少回传：

1. 复测命令与执行结果
2. 人工浏览器冒烟结论

4. 若失败，给出阻塞级别和复现路径
5. 对应 `A/F/H` 用例的通过 / 失败范围

1. 工作方预检通过

4. 高风险 Human UI 冒烟无 P0 / P1
5. 偏差已登记并裁决
