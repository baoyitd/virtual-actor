## 1. 本项目在组合中的位置

```
知识平台（真源层/A 级公共）→ 角色产品（能力层/子项目）→ 决策产品（编排层/子项目）
```

- **对上游知识平台**：我们是消费侧，提出 4 项接口需求，知识平台回可实现性反馈
- **对下游决策产品**：我们是生产侧，接收决策产品消费需求，回可实现性反馈
- **对 lead 项目**：公共契约事项上提裁决，已裁决 4 项并纳入本产品方案

## 2. 本项目负责什么，不负责什么

### 负责

- 单角色资产的创建、编辑、删除
- 角色 5 层数据模型（L1 身份 / L2 心智 / L3 知识 / L4 能力 / L5 配置）
- 角色内部生命周期管理（draft → test → published → archived）
- 角色版本化（每次发布生成不可覆写的新版本）
- 角色与知识的引用绑定关系（knowledge_refs）
- 角色测试（单次输入 → LLM 回复 → 人工评分）
- 向决策产品暴露最小公共消费接口（3 个）

### 不负责

- 议题推进、提案收敛、终稿与执行投影输出（归决策产品）
- 知识对象创建、编辑、状态流转、YAML Frontmatter 治理（归知识平台）
- 知识真源的修改和删除
- 定义公共对象命名规范、知识版本协议、组合默认集成模式（归 lead 项目）

## 3. 已裁决项

| 项 | 裁决结论 |
|----|---------|
| 角色公共字段冻结范围 | 必需 4 项 + 可选 6 项；质量信号不进公共字段集 |
| RolePublishRecord 地位 | 不进公共对象集合 |
| validated_knowledge_versions 最小结构 | knowledge_object_id + knowledge_version_id |
| API 直连定位 | 本轮允许局部实现，不升级为组合默认模式 |

## 4. 更新触发条件

1. 子项目在组合中的角色发生变化
2. 子项目依赖的公共对象或上游输入发生实质变化
3. 新的裁决结果覆盖本文档中的未写死项
