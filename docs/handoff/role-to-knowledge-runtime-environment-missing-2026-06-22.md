# 角色产品 → 知识平台 运行环境未部署公共契约接口

> 版本：v1.0 | 日期：2026-06-22
> 发起方：角色产品（Virtual Actor）
> 接收方：知识平台（Knowledge Workbench）
> 目的：角色产品在联调验证中发现运行环境未部署公共契约接口，需要知识平台给出解释

---

## 一、问题

角色产品在 v0.5.1 代码切换完成后进行联调验证，发现 Knowledge Workbench 运行环境（`localhost:3099`）**未部署公共契约接口**。

### 验证证据

| 调用端点 | 结果 | 预期 |
|----------|------|------|
| `GET /api/packages` | `{"error": "Not found"}` | 返回知识包列表 |
| `GET /api/packages/master/manifest` | 未验证（端点不存在） | 返回结构化元数据 |
| `POST /api/packages/master/retrieve` | 未验证（端点不存在） | 返回分层检索结果 |
| `GET /api/packages/master/status` | 未验证（端点不存在） | 返回 version_id |
| `GET /api/status` | 返回旧版状态（含 container/owui/managed_kbs 等字段） | 不存在公共契约版本 |
| `GET /api/health` | 正常 | 服务可达 |

当前运行的是旧版接口，公共契约接口（`/api/packages/*` 系列）尚未部署到运行环境。

## 二、需要知识平台解释的事项

1. **为什么在公共契约接口未部署到运行环境的情况下通知了"可联调"？**

   知识平台在 2026-06-22 通知"已修复，可联调"。角色产品据此完成了代码切换并启动联调验证。但运行环境实际未部署公共契约接口，联调无法进行。

2. **之前交付的"22/22 测试通过"验证的是哪个环境？**

   知识平台交付说明（`change-delivery-public-contract-2026-06-17.zh-CN.md`）声称 22/22 自动化测试通过。这些测试是在开发环境还是运行环境执行的？运行环境是否部署了与测试环境一致的版本？

3. **公共契约接口部署到运行环境的时间计划是什么？**

   角色产品代码已切换完成，当前阻塞在联调验证环节。需要知识平台给出明确的部署时间点。

## 三、当前阻塞

角色产品 v0.5.1 代码切换已完成并通过全部质量门禁（pytest 44 passed / frontend build / markdownlint / iteration-guard），但联调验证因运行环境接口缺失而阻塞。

在公共契约接口部署到运行环境之前，角色产品的角色消费功能无法正常工作——所有 retrieve 调用会返回"知识平台不可达"。
