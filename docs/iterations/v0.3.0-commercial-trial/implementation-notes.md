# v0.3.0-commercial-trial 实现偏差与关键落地说明

> 用途：记录“原预期 vs 实际实现 vs 为什么改”，避免实现和设计默默分叉

## 1. 偏差记录

| 项 | 内容 |
|---|---|
| 原预期 | 先以 prototype 验证角色产品主路径，再逐步迁移 React |
| 实际实现 | React 被确定为唯一正式用户入口，prototype 只作为迁移参考 |
| 偏差原因 | 上线验收标准调整为可交付最终用户使用的商业化产品，原型不满足正式验收 |
| 用户影响 | 用户只访问 FastAPI 托管的 React 单入口，验收对象更清晰 |
| 是否补测 | 已补 U01-U07 程序化 UI 场景链与 H01-H05 人工冒烟 |

| 项 | 内容 |
|---|---|
| 原预期 | 文件级绑定可能直接限制知识检索范围 |
| 实际实现 | 绑定保存文件级对象，测试检索按知识库 `kb_id` 去重调用 |
| 偏差原因 | 知识平台当前检索能力按 collection 级执行 |
| 用户影响 | 文件绑定用于选择与追溯，检索召回范围按知识库执行 |
| 是否补测 | 已补多知识库绑定与真实检索回归 |

## 2. 关键落地说明

1. 写接口返回前显式提交，避免刷新后读到旧状态。
2. 应用启动阶段执行 Alembic 迁移，失败直接阻断启动。
3. 知识平台不可达时，知识浏览、绑定和测试会明确阻断。
