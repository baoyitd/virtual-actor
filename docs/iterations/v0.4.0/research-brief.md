# v0.4.0 复盘研究与商业定位 Brief

> 版本：v0.4.0
> Formal Status：Draft
> 最后更新：2026-05-25
> 用途：在进入 v0.4.0 功能实现前，先完成 0.3 能力复盘、市场竞品分析、集团企业场景建模和产品定位判断

## 1. 研究目标

本轮研究不以“要做哪些功能”为起点，而是先判断角色产品的商业定位和下一轮迭代方向。

必须回答：

1. v0.3 已经构建了什么能力，这些能力是否能形成企业角色资产的基线。
2. 市场上相似产品已经覆盖了哪些能力，我们的差异空间在哪里。
3. 集团企业是否需要角色产品，如果需要，它解决什么问题，由谁使用，如何使用。
4. 角色是否应被明确为一种资产，资产应具备哪些属性和治理要求。
5. 当前角色已有设定和知识，能支持决策问答；它是否也应具备执行能力，执行边界是什么。
6. 角色资产应以什么方式让其他人或其他系统用起来。

## 2. v0.3 能力复盘

v0.3 已形成的能力基线：

| 能力 | 当前状态 | 资产意义 |
|---|---|---|
| 角色五层配置 | 已支持身份、心智、知识、能力、模型配置 | 形成角色资产的结构化定义 |
| 知识绑定 | 已支持真实知识库浏览、目录选择、绑定持久化 | 形成角色资产的知识边界和专业来源 |
| 角色测试 | 已支持真实 RAG 检索、LLM 回复、来源与分数展示 | 形成角色质量验证入口 |
| 人工评分 | 已支持测试记录评分和历史查看 | 形成角色质量反馈信号 |
| 发布与版本 | 已支持发布、不可覆写版本和知识版本追溯 | 形成可复用、可追溯的资产版本 |
| React 正式入口 | 已覆盖列表、创建、编辑、详情、测试、发布 | 形成最终用户可操作入口 |
| Docker Compose 单机部署 | 已通过验收 | 形成内部商业试用交付形态 |

当前限制：

1. 角色资产的分类、所有者、适用场景、使用权限和复用方式仍不清晰。
2. 角色主要面向问答和建议，尚未定义执行能力。
3. 角色发布后如何被其他人、其他部门或其他系统使用，仍缺产品级入口设计。
4. 模板和 AI 辅助填充只是创建效率问题，不足以单独支撑下一轮产品方向。
5. 历史版本详情和枚举中文映射是体验补齐，不是产品定位问题。

## 3. 市场与竞品观察框架

待进一步补充真实调研证据。当前先按产品类型建立分析框架：

| 类型 | 代表方向 | 已覆盖能力 | 对我们的启发 |
|---|---|---|---|
| 低代码 Agent 平台 | Coze、Dify、阿里云百炼、腾讯云 ADP、百度千帆 | Agent 创建、知识库、插件、工作流、API 发布 | 市场不缺“创建一个 Agent”，需要找企业角色资产治理差异 |
| 企业生产力 Agent | Microsoft Copilot Studio、Salesforce Agentforce、IBM AI Agents | 企业知识源、工作流动作、业务系统连接、权限治理 | 企业价值来自接入业务流程和可控执行 |
| 角色 / Persona 框架 | OpenPersona、CrewAI、Character.AI | 角色定义、目标、背景、多 Agent 协作或娱乐对话 | 可参考角色结构，但它们通常不是企业资产运营产品 |
| 知识问答平台 | FastGPT、企业知识库助手 | 知识库、RAG、问答、来源追溯 | 知识问答是底座，不是角色资产的全部价值 |

初步判断：

1. 市场已有大量 Agent Builder，但多数以“应用 / Bot / Agent”为单位，而非以“企业角色资产”为核心治理对象。
2. 企业真正需要的不是更多聊天入口，而是可复用、可授权、可测试、可发布、可追溯的虚拟专家资产。
3. 角色产品的差异点应放在资产治理、专业知识边界、质量验证、使用分发和后续执行边界，而不是单纯表单生成。

## 4. 集团企业场景假设

集团企业可能需要角色产品的原因：

1. 专家经验分散在部门、人员和文档中，难以稳定复用。
2. 管理层和一线员工都需要面向具体业务场景的专业问答和建议，而不是通用聊天机器人。
3. 业务决策需要多视角输入，例如财务、法务、风控、业务、运营、技术。
4. 企业需要知道某个 AI 角色基于哪些知识、经过哪些测试、由谁发布、适用什么范围。
5. 如果角色未来能执行任务，企业需要权限、审计、确认和责任边界。

可模拟场景：

| 场景 | 使用者 | 角色资产 | 使用方式 | 价值 |
|---|---|---|---|---|
| 经营复盘 | 管理层、经营分析人员 | 经营分析顾问 | 提问、上传材料、获得结构化分析和建议 | 降低分析准备成本，提高复盘质量 |
| 风控合规审阅 | 业务负责人、合规人员 | 风控合规审阅 | 输入方案或流程，获得风险点和整改建议 | 提前发现风险，减少反复沟通 |
| 项目治理 | 项目 owner、PMO | 项目治理助手 | 检查里程碑、交付证据、责任边界 | 提升跨部门协同和交付闭环 |
| 制度知识问答 | 普通员工、职能部门 | 制度专家 | 查询制度、流程、模板和操作边界 | 降低制度查询成本 |
| 决策辅助 | 决策产品或管理层会议 | 多角色专家组 | 被其他系统调用，形成多视角建议 | 支撑后续决策闭环产品组合 |

## 5. 角色作为资产

角色应被明确为一种企业资产，而不只是一个提示词或聊天机器人。

资产应至少包含：

1. 身份：角色名称、简介、标签、适用业务域。
2. 专业边界：负责什么、不负责什么、不能替代谁决策。
3. 知识边界：绑定哪些知识、知识版本是什么、是否过期。
4. 能力边界：能问答、能分析、能生成材料、能否执行动作。
5. 模型配置：使用什么模型、参数、成本和稳定性边界。
6. 质量证据：测试记录、人工评分、发布确认人、历史版本。
7. 使用方式：谁能看、谁能用、哪里能调用、是否可嵌入其他系统。
8. 治理信息：资产所有者、维护人、发布状态、归档策略。

v0.3 已覆盖 1 到 6 的一部分，但 7 和 8 基本未展开。

## 6. 从问答到执行

当前角色已有设定和知识，可以支持决策问答。是否扩展到执行，需要先区分三层能力：

| 层级 | 能力 | 示例 | 风险 |
|---|---|---|---|
| A1 问答建议 | 基于知识回答、分析、总结、提出建议 | 经营分析、制度问答、风险提示 | 中低，主要风险是幻觉和边界不清 |
| A2 生成产物 | 生成报告、方案、会议纪要、检查清单 | 复盘报告、整改清单、项目周报 | 中，需人工确认和格式控制 |
| A3 执行动作 | 调用工具或系统完成任务 | 创建工单、发起审批、更新项目状态、推送通知 | 高，涉及权限、审计、失败影响和责任归属 |

初步建议：

1. v0.4 不应直接做 A3 执行动作。
2. v0.4 可以研究和定义“执行能力模型”，但实现优先级应从 A2 生成产物开始。
3. 真正的 A3 执行必须先有工具权限、执行确认、操作日志、失败处理和责任边界。
4. 如果 A3 涉及其他系统读写，必须走公共契约或跨项目边界裁决。

## 7. 角色资产如何被使用

角色资产至少有四种使用方式，需要在后续范围中选择优先级：

| 使用方式 | 说明 | 可能入口 |
|---|---|---|
| 人直接使用 | 员工或管理者进入角色产品，选择角色进行问答、分析、生成材料 | React 角色详情 / 测试台升级为正式使用台 |
| 模板化复用 | 创建新角色时从企业模板库复制和调整 | 角色模板库、行业模板、职能模板 |
| 嵌入业务流程 | 在项目、风控、经营分析等流程节点调用角色 | 后续业务系统集成、工作流节点 |
| 被其他系统调用 | 决策产品或其他 AI 系统读取已发布角色版本 | 发布版本 API、角色调用 API、MCP / 本地镜像待裁决 |

v0.3 当前更接近“角色管理 + 测试台”。如果要形成商业产品，v0.4 需要判断是否应增加“正式使用台”或“资产分发 / 调用入口”。

## 8. v0.4 后续范围候选

基于当前研究假设，后续可选方向分为三类：

| 方向 | 内容 | 价值 | 风险 |
|---|---|---|---|
| P1 角色资产库 | 增加资产分类、所有者、适用场景、可见范围、使用入口 | 把角色从配置对象升级为企业资产 | 需要补产品信息架构 |
| P2 角色创建效率 | 角色模板库、AI 辅助填充 | 降低创建门槛 | 容易只解决表单效率，不解决商业使用 |
| P3 角色使用与分发 | 正式使用台、分享入口、已发布角色调用说明 | 让其他人真正用起来 | 可能触发权限、审计和 API 边界 |
| P4 执行能力模型 | 定义 A1/A2/A3，先支持生成产物或执行前方案 | 从问答走向行动 | A3 风险高，需治理和裁决 |
| P5 体验补齐 | 历史版本详情、枚举中文映射 | 降低使用阻力 | 产品增量较小 |

## 9. 当前建议

建议 v0.4 不直接命名为“模板库版本”或“AI 创建版本”。

更合适的 v0.4 方向是：

```text
v0.4.0 角色资产化与使用入口设计
```

建议优先级：

1. 先补角色资产库的产品信息架构：资产分类、所有者、适用场景、使用范围、质量状态。
2. 把“测试台”升级为“使用台”的产品设计，区分测试记录和正式使用记录。
3. 保留角色模板库和 AI 辅助填充，但作为降低创建门槛的配套能力，不作为唯一主线。
4. 执行能力先做模型和边界设计，最多进入 A2 生成产物，不直接做 A3 系统执行。
5. 历史版本详情和枚举中文映射可以作为低风险体验补齐纳入。

## 10. 待确认问题

1. v0.4 是否以“角色资产化与使用入口”为主线。
2. v0.4 是否纳入模板库和 AI 辅助填充，还是拆到后续版本。
3. v0.4 是否只定义执行能力模型，不实现 A3 执行动作。
4. v0.4 是否需要同步更新 delivery 测试计划，还是先把研究 brief 作为范围冻结前置物。
5. v0.4 是否需要向上位项目同步“角色资产”概念，确认是否会触发公共对象或跨项目契约裁决。
