## 1. 本轮目标

从原"角色资产化与使用入口"升级为"企业数字角色资产运营平台"。主线定位：

```text
v0.4.0 企业数字角色资产运营平台
```

完整表达：

```text
帮助集团企业把专家经验、岗位职责、业务知识、能力边界和 AI 能力沉淀为
可治理、可发布、可复用、可观测、可集成的数字角色资产，
并让这些角色逐步参与业务问答、决策支持、产物生成和受控执行。
```

MVP 主链路：

```text
AI 创建 -> 资产治理 -> 测试发布 -> 统一消费 -> 运营证据
```

这条链路是产品成立的底线，不应在设计层面缩减。实现可以分批（v0.4 / v0.4.x / v0.5），但设计目标不降级。

## 3. Scope Out

1. A3 执行动作的实现 — 风险高，需跨项目裁决。
2. RBAC / 多租户 / SaaS — v0.3 Scope Out 继续生效。
3. 角色模板库 — 不作为 v0.4 验收项，后续版本补足场景后重新评估。
4. 多角色协作编排 — 只定义概念，不实现委派或编排机制。
5. 消费权限校验（基于 visibility 字段） — 需公共契约裁决，v0.4 不实现。
6. 消费侧 API 版本化（/v1/ 前缀） — v0.4 不实现。
7. 流式输出（SSE/WebSocket） — v0.4 不实现。
8. MCP/A2A 协议适配 — v0.4 不实现。
9. 自定义字段配置 UI — v0.4.x 增强。
10. 不得把 v0.4 任何 mock/stub/fixture 描述为真实集成证据。

## 6. 非目标与禁止动作

1. 不在设计未收口时直接编码。
2. 不把候选需求写成已承诺交付。
3. 不自行把已确认的产品本质降级为较弱交付。
4. 不新增或修改跨项目公共契约（角色产品内部候选接口除外）。
5. 不实现 A3 执行动作。
6. 不把 DD-14 从 MVP 最终验收中移出（可延后闭合但不得移出范围）。
7. 不把 DD-16 降级为 4 状态。
8. 不把 mock/stub/fixture 描述成真实集成证据。
9. 不把知识平台当前 Accepted 范围表述为长期冻结公共契约版本。
10. 不允许"文档/API 先行、UI 后补"——进入实现前必须完成 UI/UX 原型、用户任务流、场景走查、验收点、Human 检查清单和设计冻结记录。
11. 设计冻结后不得自行改变关键交互、信息架构、流程顺序或验收语义——偏差需提交偏差说明并经规划方/终审方确认。

## 7. 验收标准

1. Dossier 一致：scope.md、design-delta.md、traceability.md 与共识稿和裁决一致。
2. 主链路可走通：AI 创建 -> 资产治理 -> 测试发布 -> 统一消费 -> 运营证据。
3. DD-01~05, 07, 08, 09~16 各项（15 项交付项，不含已移出的 DD-06/US-11 角色模板库）v0.4 必交范围通过验收。
4. 统一消费 API 可调用，返回固定治理外壳 + structured_result + 6 状态 + boundary_status。
5. 决策产品真实集成双方证据闭合（DD-14 不降级；真实集成证据闭合前不得声明 DD-14 通过，也不得声明 v0.4 完整通过）。
6. Dify 消费证明通过（角色产品侧 usage_record 与 Dify 侧调用日志对上）。
7. 6 状态验收用例覆盖基本命中路径（不得降级为 4 状态验收）。
8. UI/UX 原型、用户任务流、场景走查材料、验收点、Human 检查清单和设计冻结记录已完成并经规划方/终审方确认。
9. 质量闸门通过：iteration-guard.py + markdownlint + pytest + frontend build。
10. 交付前人工冒烟 + 偏差清单。
