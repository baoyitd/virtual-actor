## 1. 核心用户任务流

每个任务流标注：用户是谁、任务是什么、从哪里进入、每一步做什么、如何成功、如何失败、如何返回或撤销。

### 1.1 AI 协作创建角色

- **用户**：运营方 / 治理方（角色创建者）
- **任务**：用自然语言描述需求，AI 生成角色草案，确认后保存为 draft
- **入口**：资产市场 / 管理台 → [创建角色] → [AI 协作创建]

| 步骤 | 用户动作 | 系统响应 | 成功条件 | 失败条件 | 返回/撤销 |
|---|---|---|---|---|---|
| 1 | 输入角色意图描述 | 验证输入长度 >= 10 字 | 输入通过验证 | 输入过短 → 提示补充 | 点击 [取消] 返回入口 |
| 2 | 点击 [AI 生成草案] | AI 生成角色草案，展示各字段 | AI 成功生成所有字段 | AI 部分失败 → 标注失败字段，提示手动补充；AI 全失败 → 提示重新尝试或手动创建 | 点击 [重新生成] 重试 |
| 3 | 查看/编辑 AI 草案各字段 | 展示分组编辑界面 | 各字段内容合理 | 编辑后字段校验不通过 → 提示具体问题 | 点击 [取消] 返回入口 |
| 4 | 点击 [确认保存] | 弹出确认弹窗 | 用户点击 [确认保存] | 用户点击 [继续编辑] → 回到 Step 3 | 弹窗中点击 [继续编辑] |
| 5 | 确认保存 | 保存为 draft，creation_source = ai_assisted | 保存成功，跳转成功页 | 保存失败（网络异常等） → 提示重试 | 保存后无法撤销，但可继续编辑 |

### 1.2 资产市场发现角色

- **用户**：业务消费方（需要找到合适角色解决业务问题）
- **任务**：通过场景入口或 AI 推荐发现已发布角色，选择试用或查看调用说明
- **入口**：资产市场首页

| 步骤 | 用户动作 | 系统响应 | 成功条件 | 失败条件 | 返回/撤销 |
|---|---|---|---|---|---|
| 1 | 进入资产市场 | 展示场景入口 + AI 推荐输入 + 已发布角色列表 | 页面加载成功 | 无已发布角色 → 空状态提示 | 任何时候可切换视图或返回 |
| 2 | 点击场景入口或输入意图 | 展示匹配的已发布角色卡片列表 | 找到 1-3 个匹配角色 | 无匹配 → 提示"当前角色资产缺口"，记录运营信号 | 点击 [返回列表] 回到首页 |
| 3 | 查看推荐理由/角色卡片 | 展示角色详细信息（适用场景、输出类型、知识范围、版本等） | 信息完整展示 | 角色信息不完整（缺少 applicable_scenarios） → 标注"适用场景待补充" | 点击 [返回列表] |
| 4 | 点击 [试用] | 跳转到使用台消费页面 | 跳转成功 | 角色不可消费（非 published） → 提示不可试用 | 点击 [返回] 回到推荐结果 |

### 1.3 角色消费（使用台）

- **用户**：业务消费方 / 测试人员
- **任务**：输入查询，获得角色消费结果
- **入口**：资产市场 [试用] / 角色详情 [使用] / 测试台

| 步骤 | 用户动作 | 系统响应 | 成功条件 | 失败条件 | 返回/撤销 |
|---|---|---|---|---|---|
| 1 | 输入 query（可选 context） | 验证 query 非空 | 输入通过验证 | query 为空 → 按钮 disabled | 点击 [返回] 离开页面 |
| 2 | 点击 [提交查询] | 调用 consume API，展示加载状态 | API 返回响应 | API 超时/失败 → 展示 system_failed | 无撤销，可 [重新查询] |
| 3 | 查看消费结果 | 展示固定治理外壳 + structured_result + status + boundary_status | status = success，所有字段合规展示 | status 非 success → 展示相应状态信息和处理建议 | 点击 [重新查询] |

### 1.4 业务输出配置

- **用户**：运营方 / 治理方（角色编辑者）
- **任务**：为角色选择业务输出类型和确认输出字段结构
- **入口**：角色详情页 → [编辑业务输出] 或 AI 创建草案 Step 3

| 步骤 | 用户动作 | 系统响应 | 成功条件 | 失败条件 | 返回/撤销 |
|---|---|---|---|---|---|
| 1 | 选择 output_type | 展示 4 模板卡片，选中后展示对应字段列表 | 选中合法 output_type | 角色已 published → 不可修改，提示创建新版本 | 点击 [返回修改类型] |
| 2 | 查看字段结构 | 展示模板默认字段列表（逐项展示字段名、含义、必填性） | 字段列表完整展示 | v0.4 不支持自定义 → 不提供添加按钮 | 点击 [返回修改类型] |
| 3 | 点击 [确认保存] | 弹出确认弹窗（提示版本快照影响） | 用户确认 | 用户选择继续编辑 | 弹窗中 [继续编辑] |
| 4 | 确认保存 | output_type + output_schema 进入版本快照 | 保存成功 | 保存失败 → 提示重试 | 保存后需创建新版本才能修改 |

### 1.5 运营看板

- **用户**：运营方 / 治理方
- **任务**：查看角色资产运营数据
- **入口**：管理台 → [运营看板]

| 步骤 | 用户动作 | 系统响应 | 成功条件 | 失败条件 | 返回/撤销 |
|---|---|---|---|---|---|
| 1 | 进入运营看板 | 展示资产总览 + 创建运营 + 质量运营 + 使用运营 + 风险运营 | 数据加载成功 | 无角色数据 → 空状态提示 | 点击 [返回管理台] |
| 2 | 查看各维度数据 | 展示数字卡片和关键指标 | 数据正确展示 | 数据异常 → 标注异常原因 | 任何时候可返回 |

### 1.6 Dify 消费证明

- **用户**：Dify Workflow/Agent 配置者 + 终审方验收者
- **任务**：在 Dify 中配置 HTTP Tool 调用 consume API，执行代表场景，形成验收证据
- **入口**：Dify 平台 → Workflow/Agent 配置 → 添加 HTTP Tool

| 步骤 | 用户动作 | 系统响应 | 成功条件 | 失败条件 | 返回/撤销 |
|---|---|---|---|---|---|
| 1 | 在 Dify 配置 HTTP Tool | 填写 consume API URL、方法、认证、参数 | 配置完成 | 配置参数错误 → Dify 报错 | 删除或修改 Tool 配置 |
| 2 | 在 Dify 发起调用 | Dify Workflow 调用 consume API | API 返回完整治理外壳 | API 调用失败 → Dify 展示错误 | 重新执行 Workflow |
| 3 | 查看 Dify 展示的消费结果 | Dify 展示角色输出 | 展示包含 structured_result 和 status | boundary_blocked → Dify 展示阻断提示 | 修改 Workflow 逻辑 |
| 4 | 双方验收证据闭合 | 角色产品侧 usage_record 与 Dify 侧调用日志对应 | 双方证据互相对上 | 证据不匹配 → 记录偏差 | 重新执行并核对 |

### 1.7 决策产品消费证据

- **用户**：决策产品使用者 + 终审方验收者
- **任务**：在决策产品真实场景中消费已发布角色资产，形成双方验收证据
- **入口**：决策产品 → 决策事项 → 调用角色资产

| 步骤 | 用户动作 | 系统响应 | 成功条件 | 失败条件 | 返回/撤销 |
|---|---|---|---|---|---|
| 1 | 在决策产品发起决策事项 | 决策产品传入业务上下文调用 consume API | 调用成功 | 决策产品未配置 → 需双方协同 | 决策事项可取消 |
| 2 | 决策产品展示角色建议 | 展示 decision_advice 结构化结果 | 展示包含立场、理由、风险、建议 | status 非 success → 展示相应处理 | 决策事项流程可返回 |
| 3 | 双方证据闭合 | 角色产品 usage_record 与决策产品决策记录对应 | 双方证据互相对上 | 证据不匹配 → 上提治理 | 记录偏差并修复 |

## 2. UI/UX 验收点

每个核心交互的验收标准：

### 2.1 AI 协作创建

| 验收点 | 验收标准 |
|---|---|
| 意图输入 | 输入框至少 2048 字容量；空输入时按钮 disabled；<10 字提示补充 |
| AI 生成 | 加载动画显示"AI 正在生成角色草案"；生成时间 <= 30 秒 |
| 草案展示 | 所有 AI 生成字段标注"✨ AI 生成"或"✨ AI 推荐"；分组清晰 |
| 草案编辑 | 所有字段可编辑；output_type/capability_level/category 为下拉选择 |
| 保存确认 | 弹窗确认；保存后 creation_source = ai_assisted |
| AI 失败处理 | 部分失败标注失败字段；全失败提供重新尝试和手动创建两个选项 |
| 保存成功页 | 展示角色名称、状态、创建来源；提供继续编辑、进入测试台、返回三个出口 |

### 2.2 业务输出配置

| 验收点 | 验收标准 |
|---|---|
| 模板选择 | 4 模板卡片并列，选中后高亮；AI 推荐标注推荐理由 |
| 字段展示 | 每字段显示中文名、英文名、业务含义、必填性、示例值 |
| 版本快照提示 | 确认弹窗明确提示"配置进入版本快照，修改需创建新版本" |
| published 限制 | 已 published 角色 output_type 不可修改，提示"需创建新版本" |

### 2.3 资产市场

| 验收点 | 验收标准 |
|---|---|
| 场景入口 | 4 场景分类卡片可见可点击；点击后展示对应分类的 published 角色 |
| AI 推荐 | 输入意图后推荐 1-3 角色；推荐结果含推荐理由、适用问题、输出类型 |
| 无匹配提示 | 无匹配时不硬推荐，提示"当前角色资产缺口"，记录运营信号 |
| 角色卡片 | 卡片含角色名称、output_type、capability_level、业务域、适用场景 |
| 适用场景缺失 | 角色缺少 applicable_scenarios 时标注"适用场景待补充" |

### 2.4 消费结果展示

| 验收点 | 验收标准 |
|---|---|
| status 展示 | 6 状态各有独特图标和中文名称 |
| boundary_status 展示 | 4 枚举值各有独特图标和中文名称 |
| structured_result | 按 output_type 模板字段逐项展示，非 JSON dump |
| 非 success 处理 | 各状态有明确的处理建议文案 |
| 来源展示 | sources 列表可点击查看详情 |
| v0.3 fallback | output_type 为 null 时标注"该版本未配置结构化输出" |

### 2.5 运营看板

| 验收点 | 验收标准 |
|---|---|
| 资产总览 | 4 数字卡片（全部/发布/草稿/归档） |
| 创建运营 | AI 草案接受率 + 人工修改率 + 草稿沉睡数量 |
| 使用运营 | 总使用次数 + 最近使用 + 低使用 + 消费状态分布 |
| 风险运营 | boundary_blocked 比率 + undefined 比率 |
| 空状态 | 无数据时提示"创建角色后即可查看" |

## 3. Human 使用习惯专项检查清单

| 检查项 | 检查标准 | 检查方式 |
|---|---|---|
| 文案是否业务化 | 所有 UI 文案使用业务语言而非技术术语；status 中文名而非枚举值；模板字段中文名而非英文名 | 逐页面走查文案 |
| 字段是否有解释和示例 | 每个配置字段有中文说明、业务含义和示例值；output_schema 模板每字段有示例 | 逐字段检查 |
| 按钮顺序是否符合操作习惯 | 主操作按钮在右侧，取消/返回在左侧；确认弹窗确认在右，取消在左 | 逐页面检查按钮布局 |
| 危险操作是否有确认 | 发布角色、删除角色、修改 published 版本字段等不可逆操作必须有确认弹窗 | 逐操作检查 |
| 错误提示是否可理解可恢复 | 错误提示使用中文说明原因和建议动作；不使用技术错误码；提供重试/返回/替代路径 | 逐错误场景检查 |
| 长文本是否可读可滚动 | answer、structured_result 详情等长文本区域有滚动条；不截断内容 | 逐页面检查 |
| 多数据列表是否可搜索筛选 | 角色列表有基础搜索；运营看板数据按维度分组；v0.4.x 补高级筛选 | 走查列表页面 |
| 保存/发布/返回/取消状态是否明确 | 每个页面标注当前操作状态（编辑中/已保存/已发布）；按钮文案清晰（不是"OK""Submit"） | 逐页面检查 |
| AI 生成内容是否可区分 | AI 生成字段标注"✨ AI 生成"或"✨ AI 推荐"；用户可看出哪些是 AI 产出 | 走查 AI 创建流程 |
| 消费状态是否一目了然 | success 有绿色标识；非 success 有对应颜色和图标；不会把 boundary_blocked 误认为"失败" | 走查消费结果页面 |

## 4. 设计冻结记录

### 4.1 冻结范围

以下设计项在规划方和终审方确认后冻结，工作方不得自行改变：

1. **信息架构**：5 个核心页面的分区和布局（AI 创建、业务输出配置、资产市场、使用台、运营看板）
2. **核心流程顺序**：AI 创建 3 步流程（意图输入 → 草案展示 → 确认保存）不得改变
3. **消费结果展示结构**：固定治理外壳 + boundary_status + structured_result + status 的展示分区不得改变
4. **6 状态语义**：success / insufficient_context / insufficient_knowledge / boundary_blocked / system_failed / undefined 的命中规则和消费方处理方式不得改变
5. **boundary_status 复合结构**：knowledge_boundary + capability_boundary 各维度 4 枚举值不得改变
6. **4 模板字段定义**：模板必填字段不得移除，字段业务含义不得改变
7. **验收语义**：DD-14 决策产品集成必须双方证据闭合，不得单方面声明完成

## 5. 实现阶段偏差管理规则

### 5.1 偏差定义

设计偏差 = 实现阶段发现原设计不可行，需要改变冻结设计项中的关键交互、信息架构、流程顺序或验收语义。

不属于偏差的情况：

1. 技术实现细节调整（不影响交互和流程）
2. CSS 样式微调（不影响信息架构）
3. 错误文案优化（不改变错误处理逻辑）
4. 性能优化（不改变用户可见行为）

### 5.2 偏差处理流程

```text
发现设计不可行
→ 提交设计偏差说明（含以下内容）
   1. 原设计：冻结设计中规定的交互/流程/验收标准
   2. 实际限制：为什么原设计不可行（技术、性能、外部依赖等）
   3. 替代方案：建议的修改方案
   4. 影响范围：哪些 DD 项、页面、流程和验收点受到影响
   5. 验收影响：原验收标准是否需要调整，调整为什么
→ 提交规划方/终审方确认
→ 确认后方可进入实现
→ 偏差清单随交付提交
```

### 5.3 偏差清单格式

| 编号 | 原设计 | 实际限制 | 替代方案 | 影响范围 | 验收影响 | 确认状态 |
|---|---|---|---|---|---|---|
| D-01 | [描述] | [描述] | [描述] | [DD项/页面] | [调整描述] | [待确认/已确认] |

### 5.4 交付前自测要求

1. 工作方交付终审方测试前，必须先完成人工冒烟。
2. 人工冒烟覆盖所有高风险核心用户路径（7 个任务流）。
3. 记录操作人、时间、环境、步骤、预期、实际和结果。
4. 提交偏差清单；没有偏差清单视为未完成设计一致性检查。
