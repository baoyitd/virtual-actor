# v0.5.0 高保真原型范围说明

> 版本：v0.5.0 | 日期：2026-06-11 | Formal Status：Self-Tested
> 类型：设计冻结前前置材料
> 用途：记录 Design Freeze 前高保真原型的必备范围，以及当前冻结原型是如何闭合这些要求的

---

## 1. 为什么需要这份材料

当前 `v0.5` 已有：

1. 需求分析
2. 范围说明
3. 设计增量
4. 任务流和低保真线框

这些材料在当时足够做方向评审，但不足以直接进入 Design Freeze。

原因很直接：

1. `v0.5` 有一个 P0 requirement 是“角色创建 / 编辑交互重设计”。
2. 这项 requirement 的成败，高度依赖实际交互体感，而不是只靠文字描述。
3. `L3` 和 `L4` 都发生了根本性重构：
   - `L3` 从能力说明改为数据能力绑定
   - `L4` 从固定结构化输出改为 `freeform / structured` 分流
4. 如果没有高保真原型，很容易把这些关键变化留到实现后才暴露。

因此：

> **在 Design Freeze 前，关键页面必须补齐高保真原型。**

## 2. 必备高保真原型范围

以下 7 类页面必须补齐高保真原型：

### P0-1 角色定义工作台

必须回答：

1. 用户第一次进入时，是否能迅速理解“这个角色是什么”
2. 章节导航、中央编辑区、右侧进度摘要是否真的降低理解负担
3. AI 草案嵌入方式是否与手工创建共用同一工作区心智
4. 新的 `L1` 是否避免重新变成多段相近长文本输入
5. `L2` 是否明确体现“可绑定真实知识，也可明确暂不绑定”
6. `L3` 是否已经明确改成“数据能力（可选）”，并且只做选择与摘要，不再写说明性能力文案
7. `L4` 是否已经先区分 `freeform / structured`，结构化路径才展示模板与扩展
8. `model_binding` 是否已经降到高级配置，并默认继承系统值

### P0-2 消费契约 / 使用前说明卡

必须回答：

1. 消费者是否能在调用前理解角色适用性
2. “怎么用”和“为什么可信”是否足够清楚
3. 知识状态、数据能力状态、输出方式和测试摘要是否被压缩成可读卡片
4. 说明卡是否真的独立于角色定义层，而不是被塞回 `L1-L4`
5. 来源变化后，是否能明确看到`待确认更新`、重新生成和重新确认动作

### P0-3 试用与测试

必须回答：

1. `试用与测试` 是否已经独立成页，而不是挂在治理页里的附属按钮
2. 是否能清楚看出“`02` 保存当前说明卡后进入 `test`，`03` 只负责验证角色能不能工作”
3. 测试执行按钮是否留在输入区，而不是顶在页头
4. 测试失败时，是否能明确回到 `01/02` 补齐，而不是只给技术错误
5. 成功后是否自然引导到治理页，而不是让用户自己猜下一步

### P0-4 治理与发布

必须回答：

1. 硬门禁和软提示是否清楚区分
2. `structured` 路径的条件门禁是否表达清楚
3. 无知识绑定、无数据能力的合法状态是否被正确表达
4. `owner / business_domain / category` 是否真的作为“可供他人消费 / 正式发布 / 外供”阶段的硬要求成立
5. 缺失项是否能自然引导回对应补齐区块

### P0-5 数据资产管理

必须回答：

1. 管理员是否能清楚理解最小字段模型
2. 页面是否克制，没有演化成完整数据治理平台
3. 角色页与管理员页的分工是否明确：
   - 角色页只绑定
   - 管理员页才管理资产
4. 停用资产的状态联动是否直观

### P0-6 正式消费

必须回答：

1. `正式消费` 是否被清楚放在发布之后，而不是与内部测试混写
2. 是否先复用同一张说明卡，再进入正式 `consume`
3. `consume` 按钮是否留在输入区，而不是堆在页头
4. 历史消费记录是否和本次消费结果形成清晰闭环

### P0-7 外供生成面板

必须回答：

1. 用户是否理解“这是稳定供给物生成”，不是复制 API 地址
2. 版本绑定、最小说明、调用契约和回写要求是否被一眼看懂
3. Tool / Skill 两种形态切换是否清楚
4. 知识状态、数据能力状态和输出方式是否被带入供给物预览
5. 最小文件契约是否明确，不再只是示意文件名
6. “数据能力按当前生效配置运行”的限制是否被明确表达

## 3. 高保真原型评审关注点

高保真评审至少看以下 15 点：

1. 是否真的降低理解成本，而不是只换视觉风格
2. 是否仍完整承接本轮 requirement，而不是通过删内容换易用
3. 是否符合 human 使用习惯，减少显而易见的认知冲突
4. 是否明确看得出 `L1-L4` 仍是角色定义主骨架
5. 是否避免把角色定义、消费契约、资产治理重新揉回一页
6. 是否避免把 `L3` 再次做成抽象能力说明
7. 是否避免把 `L4` 重新做成“默认必须结构化输出”的旧口径
8. 是否把模板句式真正放进输入框 `placeholder`
9. 是否让“最小说明能力”在页面上真正成立
10. 是否让“稳定外供载体”被理解成产品能力，而不是技术导出
11. 是否把说明卡生命周期做成可感知的产品动作，而不是隐藏规则
12. 是否让治理主路径看起来像真正的资产治理要求，而不是表单装饰
13. 是否把“数据能力非冻结”的限制表达清楚，避免误导外部接入方
14. 是否把 `01 -> 02 保存进入 test -> 03 -> 04 -> 05/06` 的节奏表达清楚，而不是让测试继续混进治理页
15. 是否做到“页头只放当前页全局动作”，不再把跨页跳转和输入驱动动作混堆在一起

## 4. 不要求的内容

本轮高保真原型不要求：

1. 直接做成可点击前端实现
2. 覆盖系统所有页面
3. 一次确定所有视觉细节和品牌规范
4. 直接替代后续实现走查与人工冒烟

## 5. 与设计冻结的关系

当前规则固定为：

1. 低保真线框用于方向评审
2. 高保真原型用于关键交互冻结前评审
3. 未补齐本文件要求的高保真原型，不得进入 Design Freeze
