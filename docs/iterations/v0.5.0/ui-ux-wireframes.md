# v0.5.0 UI/UX 关键交互线框图

> 版本：v0.5.0 | 日期：2026-06-11 | Formal Status：Self-Tested
> 类型：低保真交互线框图
> 当前状态：已按最新需求共识同步并支撑 Design Freeze 生效；当前保留为冻结版线框参考

---

## 0. 线框约定

- 每个场景只定义信息架构和主交互，不定义最终视觉风格
- 页面主叙事必须区分：
  - `角色定义层`
  - `消费契约层`
  - `资产治理层`
- 交互上固定两类用户侧：
  - `角色能力侧`
  - `资产治理侧`
- 所有文本型字段提示统一采用：
  - 模板句式优先
  - 完整例句次之
- 模板句式优先放在输入框 `placeholder` 中
- 字段下方辅助说明只解释字段作用与边界
- 不新增定义包中心，不新增独立工作台对象

## 1. 整体导航结构

### 1.1 全局一级导航

```text
全局一级导航

01 资产市场
02 角色资产
03 运营看板
04 数据资产管理
```

固定规则：

1. 一级导航优先表达平台主任务域，不把“动作”和“页面域”并列。
2. `资产市场` 在前，服务更大规模的纯消费 / 发现人群。
3. `角色资产` 在后，服务创建、维护和带消费目的的复合用户。
4. `运营看板 / 数据资产管理` 位于后段，语义上偏向管理员与资产运营方。
5. `新建角色` 不作为一级导航项，而固定为 `角色资产` 页内主 CTA。
6. `运营看板` 对管理员先展示待处理缺口，再展示五维统计，不停留在纯数字墙。

### 1.2 角色工作区内导航

```text
侧边导航

角色主链
  01 角色定义工作台
  02 使用前说明与调用预览
  03 试用与测试
  04 治理与发布
  05 正式消费
  06 外供与追溯

配套管理
  数据资产管理（管理员页）
```

核心规则：

1. `L1-L4` 只在“角色定义工作台”里作为主骨架出现。
2. “消费契约”不再伪装成角色定义的一部分。
3. `02` 保存当前说明卡后，当前可编辑版本进入 `test`；`03` 只继续验证“这个角色能不能工作”，不再承接状态切换。
4. `04` 承接 `publish / archive`；`archived` 退出活跃市场、正式消费和新外供，但历史追溯保留。
5. `正式消费` 与 `外供与追溯` 都依赖已发布版本，但不互为前置，也不新增状态。
6. `数据资产管理` 是管理员配套页，不进入角色主链编号。

### 1.3 页面级动作治理

固定规则：

1. 页头只保留当前页面的全局动作，不放跨页面导航按钮。
2. 跨页面跳转统一由左侧阶段导航、角色概览页、阻断提示里的“去补齐”入口承接。
3. 依赖输入内容才能执行的动作，留在输入区或对应模块底部，不上提到页头。
4. 会改变阶段或版本状态的动作，必须放在承接该语义的页面里：
   - `使用前说明与调用预览` 页承接“保存当前说明卡 -> 进入 test”
   - `试用与测试` 页承接测试执行 / 复测
   - `治理与发布` 页承接发布 / 归档
   - `正式消费` 页承接 `consume`
   - `外供与追溯` 页承接生成供给物与外部回写验证
5. `使用前说明与调用预览` 的重生成动作不是常驻页头动作，只在 `待确认更新` 上下文里出现，并明确写成“根据最新角色信息重生成说明卡”。

1. 创建阶段先形成可继续编辑的 `draft`，不要求第一次进入就把治理项全部补齐。
2. 低影响字段不得继续占据主路径，应通过辅助项或高级项承接。

2. `applicable_scenarios / usage_notes / support_basis_summary` 不在此页主骨架中。
3. `category / owner / maintainer / visibility / tags / publish` 不在此页主骨架中。
4. 新的 `L1` 第一屏主路径保留 `name / bio / main_duty_cluster / point_of_view`。
5. `decision_style / identity_background / speaking_style` 进入高级项。
6. `L2` 必须同时支持两条合法路径：绑定真实知识；或明确暂不绑定真实知识。
7. `L3` 主路径只保留数据资产选择和摘要，不再出现 `capability_level / capability_boundary / collaboration_mode`。
8. `L4` 主路径先选 `output_mode`；只有 `structured` 路径下才显示 `output_type / output_schema`。
9. `model_binding` 必须折叠在高级设置中，并默认继承系统值。
10. 页头只保留 `保存草稿`；不在这里并列放“去说明页 / 去治理页”。

## 3. 使用前说明与调用预览

### 3.1 设计意图

这页回答的是：

> **别人怎么正确使用这个角色，为什么可以信它？**

它属于消费契约层，不属于角色定义层。
它的外显页面名是 `使用前说明与调用预览`，内部概念仍可保留为消费契约层。

### 3.2 线框

```text
[入口] 角色定义工作台 -> [去使用前说明]
      角色详情 / 使用台前置卡 / 测试台前置卡 -> [查看说明]

┌─────────────────────────────────────────────────────────────────────────────────────────────────┐
│ 使用前说明与调用预览                                                          [保存当前说明并进入测试] │
├────────────────────────────────────────────────────────────────────────────────────┤
│ 头部摘要（只读）                                                                    │
│ [角色名] [版本] [当前状态] [输出方式] [知识状态] [数据能力状态] [最近验证状态]      │
├────────────────────────────────────────────────────────────────────────────────────┤
│ 状态提示（仅 stale 时出现）                                                         │
│ [说明来源已变化，待确认更新] [根据最新角色信息重生成说明卡] [沿用当前文字并确认]     │
├──────────────────────────────┬─────────────────────────────────────────────────────┤
│ 这个角色适合干什么             │ 怎么正确使用                                       │
│ [一句话摘要，只读]             │ [usage_notes 预生成整段说明，可微调]               │
│ [核心职责，只读]               │                                                   │
│ [applicable_scenarios]         │ 说明别人该提供什么输入、会得到什么结果、           │
│ 系统先生成 3-5 条，用户轻量修订 │ 不要如何误用，不再拆独立“调用前提提示”字段         │
├──────────────────────────────┼─────────────────────────────────────────────────────┤
│ 你将得到什么（只读）           │ 为什么可信 / 当前限制                              │
│ 若 freeform：                  │ [support_basis_summary 主体由系统生成]             │
│   显示结果风格说明             │ [人工补充一句业务依据/限制]                        │
│ 若 structured：                │                                                   │
│   显示 output_type             │ 首屏摘要：知识状态 / 数据能力状态 / 验证状态       │
│   显示模板骨架 / 关键字段预览   │ 展开详情：知识项 / 数据资产摘要 / 最近验证摘要      │
│                               │ 事实限制：未绑定真实知识 / 未授权数据 / 暂无验证   │
└──────────────────────────────┴─────────────────────────────────────────────────────┘
```

### 3.3 固定规则

1. 这页以系统生成说明卡为主，不再是“左边三框 + 右边预览”的二次录入大表单。
2. `applicable_scenarios` 默认自动生成，仅允许轻量修订。
3. `usage_notes` 必须由系统预生成完整段落，人工再微调。
4. `support_basis_summary` 保留字段名，但交互上改为“系统生成主体 + 人工补充一句”。
5. 这页只表达事实限制，不承担 `待补齐 / 不可发布 / 不合格` 门禁判定。
6. 它不替代 `L1-L4`，但使用台 / 测试台 / 外供包应复用这里的内容。
7. 说明卡以当前保存版为唯一生效文本；来源变化后进入`待确认更新`，不自动覆盖人工修订。
8. `根据最新角色信息重生成说明卡` 只在 `待确认更新` 上下文出现，不再用模糊的“重新生成草案”文案。
9. 用户可重新生成说明卡并确认替换，也可沿用当前文本并重新保存；未确认更新前，不得发布 / 外供。
10. 若当前版本仍处于 `draft`，保存当前说明卡后应推进到 `test`；此后 `03` 只负责测试，不再承担状态切换。

### 4.1 设计意图

这页回答的是：

> **这个角色在当前版本、当前知识 / 数据 / 输出配置下，能不能先跑起来？**

### 4.3 固定规则

1. `试用与测试` 发生在 `01/02` 之后、`治理与发布` 之前。
2. `02` 保存当前说明卡会把当前可编辑版本推进到 `test`；这页只承接测试执行 / 复测，不再放置 `draft -> test` 动作。
3. 页头不放执行按钮；`test-consume` 动作固定留在输入区底部。
4. 这页复用同一张“使用前说明与调用预览”的真源与摘要字段，不再另造测试口径；但完整说明卡仍留在 `02`，测试页只显示测试前摘要与查看入口。
5. 若当前版本仍是 `draft`，这页应明确阻断并引导用户回 `02` 保存当前说明卡，而不是在这里偷偷切状态。
6. 测试失败时，应明确告诉用户回 `01 角色定义工作台` 还是 `02 使用前说明与调用预览` 补齐，而不是只给技术错误。

## 8. 外供与追溯

### 8.1 设计意图

这页回答的是：

> **这个已发布角色版本如何被外部 AI 环境稳定复用，并继续被平台追溯？**

### 8.2 线框

```text
[入口] 已发布角色版本 -> [外供与追溯]

┌────────────────────────────────────────────────────────────────────────────────────┐
│ 外供与追溯                                                                          │
├────────────────────────────────────────────────────────────────────────────────────┤
│ 当前已发布版本：role_id / role_version_id                                         │
│ [生成 Tool package] [生成 Skill package]                                          │
│ 说明：是否进入外供由生成动作显式表达，不新增独立外供开关字段。                    │
│ 说明：数据能力按当前生效配置运行，非版本冻结项；若说明或数据摘要变化，需重新生成。 │
├────────────────────────────────────────┬───────────────────────────────────────────┤
│ 左侧：供给物预览                        │ 右侧：追溯闭环                             │
│ [复用“使用前说明与调用预览”同一张说明卡] │ 调用后写入 usage_record                   │
│ package-manifest.json                   │ 追到 role_id / role_version_id            │
│ role-brief.md                           │ 保留 status / boundary_status             │
│ consume-contract.json                   │ 保留 structured_result                    │
│ output-contract.json                    │ 保留知识状态 / 数据能力状态 / 输出方式     │
│ writeback-policy.md                     │ 平台侧不绕开现有 consume 语义              │
│ Tool: tool-manifest.json                │                                            │
│ Skill: SKILL.md                         │                                            │
│                                         │ [模拟外部调用]                            │
└────────────────────────────────────────┴───────────────────────────────────────────┘
```

### 8.3 固定规则

1. 只有单个 `published role version` 才允许进入这页主路径。
2. 外供不是裸 API 导出，而是显式生成稳定供给物。
3. 外供说明必须复用同一张“使用前说明与调用预览”说明卡，不另写第二套说明。
4. 外部复用后，平台侧必须继续保留 `role_id / role_version_id / structured_result / status / boundary_status / usage_record`。
5. 外部环境不得绕开平台既有 `consume API` 运行。
6. 共同必需文件和形态专属文件都属于冻结后的最小交付契约，不是示意列表。
7. “可直接使用”的最小标准是：接入方无需手工拼接契约，只补环境配置即可在代表环境完成一次真实调用。
8. 页头不再放 `模拟外部调用`；生成供给物与外部回写验证都留在页面正文模块中。
