# 虚拟角色构建能力 — 市场调研与产品分析

> 调研日期：2026-05-13  
> 调研范围：国内外虚拟角色/Agent 构建工具、Skill 系统、多角色协作平台

---

## 一、核心发现概要

市场上已有的产品可归为三个流派：

| 流派 | 代表产品 | 核心思路 | 与我们目标的匹配度 |
|------|---------|---------|-------------------|
| **思维蒸馏派** | 女娲.skill | 从公开人物提取认知框架，生成可对话 Skill | ⭐⭐⭐ 角色构建方式可借鉴 |
| **角色定义派** | OpenPersona / CrewAI | 结构化声明角色属性（Soul/Body/Faculty/Skill 或 Role/Goal/Backstory） | ⭐⭐⭐⭐⭐ 最接近我们的目标 |
| **平台工具派** | Coze / Dify / FastGPT | 低代码搭建 Agent + 知识库 + 工作流 | ⭐⭐⭐ 能力组件可复用 |

**关键洞察**：没有一个产品同时做到"角色可定义、可携带知识库、可独立运行、可被外部系统调用"。这正是我们的机会空间。

## 二、逐产品深度分析

### 2.1 女娲.skill —— 思维蒸馏系统

**产品定位**：从公开人物的公开信息中，提炼其认知操作系统（心智模型、决策启发式、表达 DNA）。

**架构设计**：四阶段蒸馏流水线

```
Phase 1: 六路并行采集
  ├─ 著作 Agent
  ├─ 播客/访谈 Agent
  ├─ 社交媒体 Agent
  ├─ 批评者视角 Agent
  ├─ 决策记录 Agent
  └─ 人生时间线 Agent

Phase 2: 三重验证提炼
  ├─ 跨域重现：观点在 ≥2 个不同领域出现过
  ├─ 有预测力：能推断对未知问题的立场
  └─ 有排他性：具有该人物的独特印记

Phase 3: 构建 Skill → SKILL.md
  ├─ 3-7 个心智模型
  ├─ 5-10 条决策启发式
  ├─ 表达 DNA
  └─ 诚实边界

Phase 4: 质量验证
  ├─ 已知问题方向一致性测试
  └─ 未知问题适度不确定性测试
```

**角色构成**：五层递进式

| 层次 | 内容 | 对应产物 |
|------|------|----------|
| 怎么说话 | 表达 DNA – 语气、节奏、用词偏好 | 表达 DNA |
| 怎么想 | 心智模型、认知框架 | 心智模型（3-7 个） |
| 怎么判断 | 决策启发式 | 决策启发式（5-10 条） |
| 什么不做 | 反模式、价值观底线 | 价值观与反模式 |
| 知道局限 | 诚实边界 | 明确标注"做不到什么" |

**对我们的启发**：
- ✅ 角色的"思维框架"比"人设扮演"更有实用价值
- ✅ 五层定义结构可借鉴，尤其是诚实边界（知道什么不做）
- ✅ 配套的"达尔文.skill"评估进化体系，保证角色质量
- ❌ 仅从公开资料蒸馏，不支持自定义角色（不适用我们的"按需构建"）
- ❌ 没有知识库概念，不基于文档回答
- ❌ 输出是 Claude Code Skill，不独立运行，也不支持被外部调用
- ❌ 作者：花叔（独立开发者），MIT 开源，GitHub 27 commits，Stars 破万

### 2.2 OpenPersona —— 四层 Persona 框架

**产品定位**：开源、Agent 无关的 AI Persona 全生命周期框架，声明式定义+运行时约束。

**角色构成**：Soul · Body · Faculty · Skill

```
┌─────────────────────────────────────────────────┐
│               OpenPersona 四层架构                │
├─────────────────────────────────────────────────┤
│ Soul 层    │ 你是谁？                             │
│            │ personaName, bio, personality,       │
│            │ speakingStyle, constitution.md       │
│            │ → 支持灵魂进化（evolution）            │
├────────────┼─────────────────────────────────────┤
│ Body 层    │ 你运行在哪里？                        │
│            │ runtime（OpenClaw/Cursor/etc.）       │
│            │ appearance, interface 契约            │
├────────────┼─────────────────────────────────────┤
│ Faculty 层 │ 你有什么持久能力？                     │
│            │ Expression（TTS）, Sense（视觉/情绪）  │
│            │ Cognition（跨会话记忆）                │
├────────────┼─────────────────────────────────────┤
│ Skill 层   │ 你能执行什么动作？                     │
│            │ 内置技能（selfie/music/reminder）     │
│            │ 外部技能包（web-search 等）            │
└────────────┴─────────────────────────────────────┘
```

**最小可行 Persona 只需 5 个字段**：personaName, slug, bio, personality, speakingStyle

**关键设计亮点**：
- 通过 3 个门（生成/安装/运行时）保证 Persona 安全一致
- 支持 Fork 和 Lineage（血缘追踪），角色可以派生和演化
- 可声明 trust 级别进行运行时门控
- 兼容 skills.sh 协议，可与 OpenClaw/ClawHub 互通
- **Soul 层支持 evolution**：记录关系阶段、情绪、特质变化、风格漂移

**对我们的启发**：
- ✅ Soul/Body/Faculty/Skill 四层划分非常清晰，可直接参考
- ✅ 声明式定义 + 自动推导的方式降低角色创建门槛
- ✅ Body 层分离了"角色定义"和"运行环境"，天然支持独立运行+被调用
- ✅ 开源 MIT 协议，可复用（acnlabs 组织，v0.20.1，2026-03-29）
- ❌ Faculty 层侧重感官能力（语音/视觉），没有知识库模块
- ❌ 没有对话管理界面，偏底层框架
- ❌ Skill 层是动作技能，不是"基于知识库的问答能力"

### 2.3 CrewAI —— 角色驱动的多 Agent 框架

**产品定位**：Python 多 Agent 编排框架，"特种部队"模式，角色定义 + 任务分配。

**角色定义方式**（Agent 对象）：

```python
agent = Agent(
    role='资深AI行业分析师',          # 职位/身份
    goal='发掘市场动态和技术趋势',     # 目标/OKR
    backstory='你曾在顶级咨询公司工作10年...',  # 背景故事
    tools=[search_tool],              # 工具/技能
    llm=ChatOpenAI(model="gpt-4"),    # 指定 LLM
    allow_delegation=False,           # 是否允许委派
    verbose=True                      # 日志级别
)
```

**协作模式**：
- Sequential（顺序执行）：研究员 → 分析师 → 作家
- Hierarchical（管理器分配）：一个 Manager Agent 动态调度

**对我们的启发**：
- ✅ 每个 Agent 可指定独立的 `llm` 模型，天然支持多模型
- ✅ role + goal + backstory + tools 的字段组合简洁实用
- ✅ 支持 allow_delegation 协作模式
- ❌ 没有知识库概念，tools 是搜索/API 等外部工具
- ❌ 是代码框架，不是产品形态，无法独立运行
- ❌ 没有角色管理/存储/复用体系

### 2.4 Coze / Dify / FastGPT —— AI Agent 平台三杰

| 维度 | Coze（字节跳动） | Dify（开源） | FastGPT（开源） |
|------|-------------|-------------|----------------|
| **定位** | 零代码对话机器人 | AI 应用开发平台 | 知识库问答平台 |
| **角色定义** | 人设 + 提示词 | 系统提示词 | 系统提示词 |
| **知识库** | ✅ 基础支持 | ✅ 私有化部署 | ✅✅✅ 专精 RAG |
| **多模型** | ✅ 支持多模型 | ✅ 支持多模型 | ✅ 支持多模型 |
| **工作流** | ✅ 可视化编排 | ✅✅ 强大工作流 | ✅ 基础工作流 |
| **多角色** | ❌ 单 Bot | ❌ 单 App | ❌ 单应用 |
| **外部调用** | ✅ API | ✅ API | ✅ API |
| **开源** | ❌ | ✅ | ✅ |
| **适合谁** | 零基础快速验证 | 有技术团队的深度定制 | 知识库场景专项 |

**对我们的启发**：
- ✅ FastGPT 的知识库 RAG 能力可作为技术参考
- ✅ Dify 的工作流编排可参考（未来角色协作场景）
- ❌ 三者都是"单 Bot/单应用"模式，不支持多角色管理
- ❌ 角色定义仅靠提示词，没有结构化角色模型
- ❌ 角色是为"对话"设计的，不是为"被其他 Agent 调用"设计的

### 2.5 Character.AI / OpenCharacter —— 角色扮演平台

| 维度 | Character.AI | OpenCharacter（开源替代） |
|------|-------------|--------------------------|
| **定位** | 娱乐角色扮演 | 开源替代 |
| **角色定义** | 名称 + 描述 + 问候语 + 提示词 | 同上 + 支持本地 LLM |
| **知识库** | ❌ 无 | ❌ 无 |
| **多角色** | ✅ 多角色切换 | ✅ |
| **场景** | 娱乐对话 | 通用角色 |
| **开放性** | ❌ 封闭平台 | ✅ 开源可自部署 |

**对我们的启发**：
- 角色扮演产品市场成熟，但缺乏"知识库 + 实用性"
- 我们的产品应走"实用性角色"路线而非"娱乐角色"
- OpenCharacter 的模式可参考：自部署 + 多模型 + 角色管理 UI

### 2.6 多 Agent 协作框架全景对比

| 框架 | 角色定义方式 | 知识库 | 多模型/单Agent | 协作模式 | 独立运行 |
|------|------------|--------|----------------|---------|---------|

- 不支持角色持久化存储和复用
- 无知识库管理能力
- 需要写 Python 代码，无 UI

## 三、市场空白与机会

```
现有产品的覆盖矩阵：

                    角色结构化定义   知识库/RAG   多模型独立配置   独立运行   可被外部调用
女娲.skill              ✅              ❌            ❌           ✅          ✅
OpenPersona             ✅✅            ❌            ❌           ✅          ✅
CrewAI                  ✅              ❌            ✅           ❌          ❌
Coze/Dify/FastGPT       ❌              ✅            ✅           ✅          ✅
Character.AI            ❌              ❌            ❌           ✅          ❌

我们的目标               ✅✅            ✅            ✅           ✅          ✅✅
```

**三个核心机会点**：

1. **"全栈角色"空白**：没有一个产品同时兼备"结构化角色定义 + 知识库 + 多模型 + 可独立运行 + 可被集成"
2. **"角色专属知识库"概念缺失**：现有产品的"知识库"都是全局知识库，没有"这个角色独有的知识"和"跨角色共享的知识"的区分
3. **"角色作为可调用能力单元"空白**：现有平台的角色都是为"人机对话"设计，没有一个产品把角色设计为"可被其他系统调用参与决策/执行的 API 级能力单元"

## 四、对我们产品设计的建议

### 4.1 核心差异定位

> **不是聊天机器人，不是角色扮演，而是"可调用、可组合的虚拟专家"**
> 
> 一句话价值主张：**构建、管理和调用具有专属知识的虚拟角色，让他们参与你的 AI 工作流。**

### 4.2 建议的角色构成模型（5 层）

综合 OpenPersona（4 层）+ 女娲.skill（5 层认知）+ CrewAI（Role/Goal/Llm）：

```
┌─────────────────────────────────────────────────────────┐
│                  Virtual Actor 角色模型                    │
├───────┬─────────────────────────────────────────────────┤
│  L1   │  身份 Identity                                  │
│       │  名称、头像、一句话简介、角色标签/分类               │
│       │  参考：OpenPersona Soul.bio                       │
├───────┼─────────────────────────────────────────────────┤
│  L2   │  心智 Mind                                      │
│       │  定位描述（Role）、目标（Goal）、                      │
│       │  思维框架（心智模型/决策启发式）、                      │
│       │  表达风格（语气/用词偏好）、诚实边界                   │
│       │  参考：女娲.skill 五层 + CrewAI Role/Goal            │
├───────┼─────────────────────────────────────────────────┤
│  L3   │  知识 Knowledge       ← 【核心创新层】               │
│       │  专属知识库（该角色独有文档/数据）                     │
│       │  公用知识库（跨角色共享的基础知识）                     │
│       │  知识范围边界（明确"我知道什么/不知道什么"）             │
│       │  参考：FastGPT RAG + 女娲.skill 诚实边界             │
├───────┼─────────────────────────────────────────────────┤
│  L4   │  能力 Capability                                │
│       │  可调用工具/技能（搜索/计算/API 等）                   │
│       │  协作模式（独立决策 / 可委派 / 仅咨询）                 │
│       │  能力诚实声明（"我的能力边界"）                        │
│       │  参考：OpenPersona Skill + CrewAI Tools             │
├───────┼─────────────────────────────────────────────────┤
│  L5   │  配置 Config                                    │
│       │  LLM 模型选择（GPT-4o / Claude / 通义千问...）        │
│       │  模型参数（temperature, max_tokens...）             │
│       │  记忆策略（会话记忆长度 / 摘要策略）                   │
│       │  API 端点暴露配置                                  │
│       │  参考：CrewAI llm 参数                              │
└───────┴─────────────────────────────────────────────────┘
```

### 4.4 典型使用场景

```
场景 1：多角色决策
  决策系统 ──POST /api/roles/{id}/consult──→ 财务专家角色
           ←── 基于财务知识库的分析观点 ──
           ──POST /api/roles/{id}/consult──→ 法务专家角色
           ←── 基于法务知识库的分析观点 ──
  决策系统汇总各方观点 → 做出决策

场景 2：AI 编程 Agent 增强
  IDE Agent → 加载"资深架构师"角色
           → 代码审查时注入架构师的审查标准和思维框架

场景 3：内容创作流水线
  编排系统 → 依次调用"市场研究员"→"内容策划"→"文案作家"
           → 每个角色基于自己的专属知识库输出结果

场景 4：企业内部知识问答
  员工 → Web UI 选择"产品专家"角色
       → 询问产品规格问题
       → 角色基于产品文档知识库回答 + 引用来源
```

## 五、下一步讨论

在进入技术实现前，建议先确认：

1. **角色构成模型**：5 层结构（身份/心智/知识/能力/配置）是否合理？需要增减什么？
2. **MVP 范围**：建议第一版聚焦 角色管理 + 知识库 + 单角色对话 + REST API，后续再扩展多角色协作
3. **产品原型**：是否先出 UI 原型（角色创建页、对话页、知识库管理页）？
4. **命名**：Virtual Actor 作为项目名是否确定？
